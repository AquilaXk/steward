# Steward 수정 검토

정책 엔진, 저널, 검증, 설치 코드를 검토하고 네 가지 결함을 수정했다.
패키지·CLI·스킬·환경변수·상태 경로는 `steward`로 통일했다.

## 수정한 동작

- 파일 실행 권한 비트를 소스 스냅샷에 포함한다. 검증 후 실행 권한을 제거하면
  기존 증거는 `STALE_SOURCE`로 거부된다. 이전 스냅샷의 증거는 재검증해야 한다.
- 저널을 읽을 때 envelope, 파일명과 ID, 타입별 데이터, 내부 verification 데이터를
  검사한다. 해시가 일치해도 잘못된 형식은 `JOURNAL_CORRUPT`로 거부한다.
- 체크포인트는 같은 세션 해시로만 선택한다. 이름이 있는 세션은 다른 세션이나
  세션 없는 기록을 대신 사용하지 않는다. 세션 없는 호출은 세션 없는 기록만 선택한다.
- 훅 설치는 전체 파일 대상을 사전 확인한다. 중간 쓰기 실패 시 완료된 파일 변경을
  복구한다. 복구 실패는 `INSTALL_RECOVERY_REQUIRED`와 해당 경로로 보고한다.

`checkpoint --file FILE --session-id HOST_SESSION_ID`는 세션 ID의 SHA-256만 저장한다.
호스트의 정확한 ID를 모르면 추측하지 않는다. 세션 없는 기록을 남길 수 있지만,
이름이 있는 호스트 세션에서 자동 복원된다고 주장하지 않는다.

## 검증 근거

수정 전 추가한 회귀 사례 11개가 모두 실패했고, 최초 수정 후 모두 통과했다.
실행 권한 변경, 해시가 올바른 잘못된 저널, 세션 간 혼용, CLI 세션 저장,
설치 사전 검사 및 쓰기 실패 복구를 실제 임시 파일과 프로세스로 검사한다.
전체 테스트에서 추가로 확인한 경로 별칭 문제는 실제 프로젝트 경로를 기준으로 신뢰와
호스트 작업 디렉터리를 비교하도록 수정했다. 별칭을 통한 프로젝트 내부 신뢰 저장도
거부한다. 해당 회귀 사례 역시 수정 전 실패와 수정 후 통과를 확인했다.
기존 압축본의 출력은 현재 결과로 재사용하지 않는다. 최종 명령·환경·결과는
[검증 기록](../evidence/VERIFICATION.md)과 원시 출력에 남긴다.

기존 어댑터 테스트 두 개와 데모는 이름이 있는 세션을 사용하므로,
체크포인트에도 그 세션 해시를 지정했다. 압축 상태 저장, 복원 내용, 익명화에 대한
기존 검증은 유지한다. 새 테스트는 다른 세션 및 세션 없는 기록으로의 대체를 금지한다.

## 남은 운영 한계

- 실제 Codex·Claude 호스트에서의 스킬 발견, 훅 차단과 복원은 아직 관찰하지 않았다.
  로컬 어댑터 테스트와 실제 호스트 검증은 구분한다.
- 검증 명령의 직접 자식만 제한한다. 모든 하위 프로세스의 종료를 보장하지 않는다.
- 스냅샷에는 심볼릭 링크 대상 내용, 외부 서비스 상태가 포함되지 않는다.
  중첩 의존성·빌드 출력의 자동 제외나 임의 성공 대체도 없다.
- 기존 설치를 자동 이전하거나 사용자 수정 스킬을 자동 병합하지 않는다.
  새 설치의 `.steward/USAGE.md`, `skipped`와 실제 파일을 확인해야 한다.
- 설치 중 프로세스 강제 종료·전원 손실은 자동 롤백으로 보장하지 않는다.
  일반 쓰기 오류는 복구하지만 복구 불가 시 명시적인 운영자 확인이 필요하다.
- 저널은 전체 체인을 읽는다. 장기 보관·대량 조회·지침 감사 범위 확대는 별도 과제다.

해시 검사는 작성자 인증이나 운영체제 격리를 제공하지 않는다. 모델 API 호출,
실제 사용자 호스트 설치와 운영 서비스 배포는 수행하지 않는다. 공개 소스 준비에서는
영문·한국어 README와 스킬 지침을 보완했다. 원격 공개와 CI 결과는 GitHub에서 확인한다.
